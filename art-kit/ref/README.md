# ref/ — 참조 그림

Codex에 `-i`로 붙이는 그림이다. 모두 '용사의 대장간'에서 Codex가 뽑아 **채택한 원본 PNG 그대로**다
(줄이거나 다시 저장하지 않았다. 게임의 처리 결과 `meta.json`의 잘라 낸 상자와 1px까지 맞는 것을 확인했다).
`tools/manifest.ts`의 `REF_IMAGES`가 이 파일들을 이름으로 부른다. 한눈에 보려면 `../samples/refs.png`.

## 규칙 두 가지

1. **`d_dwarf_idle.png`는 모든 그림의 첫 참조다.** 드워프를 그리지 않는 그림(아이콘, 건물, 몬스터)에도 붙인다.
   화풍 머리말(STYLE)이 "the attached dwarf character image"라고 부르기 때문이다. 대신 프롬프트에
   "STYLE REFERENCE ONLY … do NOT draw the dwarf"를 적는다 (`STYLE_REF_ONLY`, `MON_REF_NOTE`, `CHAR_REF` 등).
2. **두 번째 참조는 같은 세트의 '기준 그림' 한 장이다.** 선 굵기, 틀 안의 크기와 여백, 시점, 채색을 맞추게 한다.
   기준 그림 자신은 드워프 하나만 참조로 뽑는다. 프롬프트가 "second attached image"라고 부르므로 순서를 바꾸지 않는다.
   참조는 원하지 않는 것까지 베낀다. 따르지 말아야 할 디자인은 하나하나 금지한다 (아래 '조심할 것').

## 파일

외곽선은 `node tools/inspect.ts ref`로 잰 값이다: 짙은 갈색 외곽선이 이어지는 길이의 중앙값(px)과, 괄호 안은 캔버스 **짧은 변**을 1024로 환산한 값
(1254×1254로 나온 그림과 1024×1024 그림을 견줄 때 쓴다. 1024×1536 세로·1536×1024 가로는 짧은 변이 1024라 그대로다).
새 그림을 같은 도구로 재어 세트 기준과 비교한다. 원래 게임에서는 세트 기준보다 2px 넘게 가늘면 다시 뽑았다.

## 새 기준 그림을 더할 때

1. 새 세트의 첫 장을 드워프 하나만 참조로 뽑는다 (예: `icon('element_light', '빛 속성', null, '...')`).
2. 채택하면 그 원본을 다른 그림의 두 번째 참조로 `'@icons/element_light'`처럼 부른다 (원본 폴더에서 바로 찾는다).
3. 이름으로 부르고 싶거나 다른 프로젝트로도 옮길 기준이면, 원본 PNG를 프로젝트 쪽 폴더(예: `<프로젝트>/tools/art-ref/`)에 두고
   프로젝트 파일(`art-assets.ts`)의 `PROJECT_REFS`에 한 줄 더한다: `export const PROJECT_REFS = { hero_lead: { file: './art-ref/hero_lead.png', note: '...' } };`
   키트의 이 폴더와 `tools/manifest.ts`는 고치지 않는다 (키트를 새 판으로 바꿀 때 덮어쓰인다).

원본 PNG는 줄이거나 다른 형식으로 다시 저장하지 않는다. 원래 게임은 늘 Codex가 낸 원본을 그대로 보냈다.
