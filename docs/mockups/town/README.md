# 마을 지도 시안 (기획서 3.8)

홈 화면 마을 지도의 그림 시안이다 (2026-10-13). 바닥과 건물을 따로 뽑아 합쳤다.
게임의 홈 화면(마을 지도, `src/render/town`·`src/ui/town`)은 이 폴더의 `layout.json`을 그대로 읽어, 같은 그림(`src/assets/art/town`)으로 같은 순서·같은 그림자로 PixiJS에 그린다 (아래 '게임에서').

## 파일

| 파일 | 크기 | 내용 |
|---|---|---|
| `full.webp` | 1327 x 2400 | 지도 한 장. 원래 2458 x 4446 px를 세로 2400px로 줄였다 |
| `overview.webp` | 774 x 1400 | 줄인 전체 |
| `view_forge.webp` · `view_plaza.webp` · `view_towers.webp` | 780 x 1688 | 폰 화면 셋. 지도 1:1(390pt 폰의 2배 px)에 UI 목업을 얹었다 |
| `assets.webp` | 1878 x 2966 | 쓴 그림 목록. 맨 위 줄은 검토 뒤 다시 뽑은 그림의 이전 판과 새 판 |
| `layout.json` | | 합성 결과의 배치 그대로 (아래 'layout.json') |

WebP는 품질 0.85로 헤드리스 크롬 canvas에서 만들었다. 원본 PNG는 저장소 밖 작업 폴더에 있었다.

## 그림

- 바닥, 구름 띠, 건물 10, 탑 4, 소품 13. 모두 29키다. 키마다 프롬프트·크기·참조·메모가 `tools/art/assets.ts`의 그룹 `town`에 있다. 처리본은 `src/assets/art/town/*.webp`와 `src/assets/art/meta.json`의 `town`에 있다.
- 쓰지 않은 바닥 후보 `ground_a`(강과 다리, 십자 길)는 `assets.ts`에 메모로만 남겼다.
- 걷는 사람은 영웅 예제 그림 10장과 드워프 기준 그림 `tools/art/ref/d_dwarf_idle.png`를 줄여 놓았다. 영웅 예제는 `tools/art/assets.ts`의 그룹 `heroes`(프롬프트)와 `src/assets/art/heroes/*.webp`(긴 변 400px)에 보존했다.
- UI 목업의 아이콘은 `src/assets/art/refine`의 골드, 덩어리, 가방이다. 메뉴의 대장간과 길드 아이콘은 그 건물 그림이다.

## 합성

`tools/art/town/compose.ts`가 헤드리스 크롬을 띄우고 `page.js`가 canvas에 그린다. 배치와 수치는 `layout.ts`에 있다.
수치에는 두 가지 단위가 있다. 지도 px는 지도 위의 자리와 크기이고, 원본 px는 생성된 PNG의 좌표다.

그리는 순서는 아래와 같다.

1. **하늘과 바닥.** 위 760px는 평면 하늘(#CFE3EA)이다. 그 아래에 `ground_b`(1024 x 1536)를 2.4배로 키워 깐다. 키운 바닥에서 짙은 갈색 잉크 선을 양쪽 3px씩 깎았다(`thinInk`). 깎을 때는 선 픽셀마다 가장 가까운 비잉크 픽셀 너머의 색을 가져온다. 그래야 길·절벽 선(약 9px)이 건물 선(약 8px)과 비슷해진다. 선명하게 하기(unsharp)는 테두리 번짐이 생겨 껐다.
2. **흙 오솔길.** 문 앞에서 큰길까지 낸 길이다(광산, 길드, 대장간, 재료 상점, 여관, 왼쪽 집). 채움은 길 모래색이다. 잉크 테두리는 풀 위에만 그려서, 큰길과 만나는 곳에서는 큰길 테두리가 열린다.
3. **지평선 구름.** 고원 너머에 낮은 구름 줄을 깔아 바닥 그림의 위 끝을 가린다. 구름은 원을 겹쳐 그린다. 잉크 테두리를 두르고, 아래는 청회색(#DCE4EA), 위는 흰색(#F7F9FA)으로 칠한다.
4. **그림자 층.** 그림마다 구워진 회색 그림자를 떼어 낸다. 투명한 곳에서 밝은 픽셀을 따라 채워 가고, 잉크 선에서 멈춘다. 채도가 낮은 큰 덩어리만 그림자로 본다. 떼어 낸 그림자와 바닥 접지 타원(빛이 왼쪽 위라 오른쪽 아래로 조금 민다)을 한 층에 모아 #c3cba6로 곱하기(multiply)를 한 번 한다. 흐리게 하지 않고 두 번 어둡게 하지 않는다. 뒤집은 그림은 접지 타원만 쓴다. 마을 문은 기둥과 울타리마다 접지 그림자를 따로 적었다.
5. **그림.** 땅에 닿는 점의 y 순서로 뒤에서 앞으로 그린다. 배율은 원본 px당 지도 px다.
   - 건물·탑: `F × rel`, F = 0.5. 대장간 1.2, 길드 1.1, 탑 1.2, 집 0.65~0.7.
   - 소품: 몸통 높이를 지도 px로 정했다.
   - 사람: 한 배율을 쓴다. 영웅 0.094, 드워프 0.1025.
   - 작게 그리는 소품과 사람에는 원본에 바깥 잉크 테두리를 덧그려 건물과 선 굵기를 맞췄다. 상자 18, 꽃 16, 벤치·화분 14, 울타리 12 원본 px이고, 영웅은 24, 드워프는 20이다.
6. **탑의 층 쌓기.** 탑마다 한 층을 잘라 위로 쌓아 끝없이 오르게 했다. 한 층은 창 하나 위의 맨 벽에서 다음 창 위의 맨 벽까지(원본 px 행)다. 물 580~908행 8번, 불 585~904행 9번, 땅 580~900행 8번, 바람 590~908행 9번 쌓는다. 층마다 0.95배로 줄이고, 벽이 계단 없이 가늘어지게 층을 행마다 휘었다. 이음매는 10행을 겹쳐 흐리게 잇는다. 모든 탑이 지도 위 끝 밖까지 올라가서 꼭대기는 보이지 않는다.
7. **굴뚝 연기.** 대장간 굴뚝에서 오른쪽 위로 흘러가는 작은 구름 무리다. 연기는 대장간의 표시라 다른 집에는 그리지 않았다.
8. **구름 고리와 구름 띠.** 탑이 구름으로 들어가는 자리를 구름 고리로 감싼다. 탑마다 높이가 다르다. 그 위에 `cloud_band` 그림의 윗부분(원본 0~530행)을 360px 높이로 줄여, 지도 폭만큼 좌우로 뒤집어 가며 이어 붙인다.

폰 화면은 지도에서 780 x 1688을 잘라 UI 목업을 얹은 것이다. 위 94px(노치)는 비우고 그 아래에 골드·덩어리 칩과 장소 이름표를 둔다. 아래 68px(홈 표시줄) 위에는 메뉴 버튼 넷(대장간·정제·길드·가방)을 둔다. UI는 크림 종이(#F6EBD5)에 5px 갈색 선을 두르고, 흐림 없는 6px 그림자를 붙였다. 글꼴은 이 PC에 있는 Malgun Gothic이다. 게임의 Jua는 설치돼 있지 않다.

## 지나온 길

1. **첫 회차.** 바닥 후보 둘, 건물 10과 탑 4, 소품 10을 뽑았다. 건물은 첫 판 대장간을, 소품은 둥근 나무를 두 번째 참조로 받았다.
2. **첫 합성.** `ground_b`를 2배로 키웠다. 구름은 크림색으로 그렸고, 대각선 마을 문은 기울이고 늘렸다.
3. **검토.** 시안 방향은 맞다고 봤다. 고칠 것으로 나온 것은 아래와 같다.
   - 대장간이 집만 하고 간판이 한글처럼 읽힌다.
   - 구름이 UI 종이색과 같아 탑이 끝없이 이어져 보이지 않는다.
   - 길 선이 건물보다 두 배 굵다.
   - 광장이 비어 있다.
   - 건물 문 앞에 길이 없다.
4. **둘째 회차.** 다시 뽑은 그림은 대장간(넓은 열린 작업장), 정면 대칭 마을 문, 바닥(선을 얇게, 고원을 깊게, 덤불·바위 없이), 구름 띠다. 새로 뽑은 그림은 벤치, 꽃 화분, 노점 수레다. 배치도 아홉 가지를 고쳤다(탑 층 쌓기, 하늘 여백, 대장간 키우기, 광장 꾸미기, 오솔길, 빈 구역, 아래 여백, 선 굵기, 바닥의 덤불). 지금 파일은 이 회차의 결과다.

## 남은 문제

- 선 굵기가 아직 고르지 않다. 길·절벽 약 9px, 대장간·탑 약 8px, 작은 집 약 6px, 사람 3~4px이다.
- 바닥은 2.4배로 키운 것이라 1:1로 보면 그림보다 조금 흐리고, 선 둘레에 옅은 번짐이 남았다.
- 탑 이음매에서 땅의 탑 덩굴이 조금 어긋나고, 불의 탑 불꽃 띠가 조금 비친다. 폰 크기에서는 작다.
- 구름 띠를 뒤집어 이었기 때문에 이음매 둘(지도 x 약 900, 1940)에서 좌우 대칭이 보인다. 띠의 틈으로 땅의 탑이 구름 위로 이어져 보이는데, 구름을 뚫는 탑으로 읽혀서 두었다.
- 탑이 모두 지도 밖까지 올라가 8·9층의 차이는 보이지 않는다. 차이는 받침 깊이(1170, 1235)와 구름 고리 높이에서 난다.
- 마을 문만 정면을 본다. 다른 건물은 조금 돌아 왼쪽 아래를 본다. 대장간 둘째 판과 꽃 화분은 다른 건물보다 조금 더 아이소메트릭 쪽이다.
- 시장 노점(두 노점이 한 그림)이 광장 왼쪽 아래 귀퉁이에서 풀 위로 조금 걸친다.
- 사람은 서 있는 그림을 뒤집어 방향만 냈다. 걷는 그림은 없다.

## layout.json

합성기가 쓴 그대로다. 값은 아래를 뜻한다.

- `map`: 지도 크기, 바닥 배율(2.4), 하늘 높이(760). `items[]`: 놓은 그림마다 다음 값이 있다.
  - `x`, `y`: 땅에 닿는 점(지도 px)
  - `scale`: 원본 px당 지도 px
  - `flip`
  - `box`: 그린 몸통 상자(지도 px)
  - `anchor`: 잘라 낸 그림 안의 기준점 비율
  - `ell`: 접지 타원의 크기 비 (울타리처럼 낮은 소품), `spots`: 접지 타원 대신 직접 적은 그림자 (마을 문의 기둥과 울타리마다, 기준점에 대한 지도 px)
- `map.thin`: 바닥 잉크 선을 양쪽으로 깎은 폭(지도 px).
- `paths`, `towers.stack`, `clouds`(지평선, 고리, 띠), `smoke`(대장간 굴뚝 연기의 구름 무리와 색), `outlines`(작은 소품과 사람에 덧그린 바깥 잉크, 원본 px. 사람의 배율), `views`(폰 화면 자리)는 위 '합성'의 수치다.
- `ell`, `spots`, `map.thin`, `smoke`, `outlines`는 게임이 같은 그림자와 선을 그리려고 2026-10-13에 더했다 (합성기 `page.js`가 쓰고, 지금 파일에는 `tools/art/town/layout.ts`의 같은 값을 옮겨 적었다). 나머지 값은 그대로다.
- `views[].file`은 합성할 때의 이름(`town_view_forge.png`)이다. 여기 있는 파일은 `view_forge.webp`다.
- 원본 px 좌표는 생성된 PNG 기준이다. 처리본 WebP(`src/assets/art/town`)는 잘라 줄인 그림이다. 원본 px로 되돌리려면 `meta.json`의 `trim`(원본 안의 사각형)과 `scale`을 쓴다.

## 다시 만들기

그림을 다시 뽑는다:

```
node tools/art/gen.ts town/bld_forge --out <원본 폴더> --ref tools/art/ref
node tools/art/process.ts --raw <원본 폴더> --only town/bld_forge
```

`bld_gate`와 `ground_b`는 자기 키를 두 번째 참조로 받는다. 다시 뽑기 직전의 지금 원본을 보고 고쳐 그린다는 뜻이다.

다시 합성한다:

```
node tools/art/town/compose.ts --out docs/mockups/town [--raw <원본 폴더>] [--heroes <영웅 예제 원본 폴더>]
```

게임의 지도 그림을 다시 굽는다 (`layout.json`, `src/assets/art/{town,heroes}`의 그림이나 `meta.json`, 손님 키 `GUESTS.height`를 바꾼 뒤. 안 구우면 `tools/art/town/bake.test.ts`가 실패한다):

```
node tools/art/town/bake.ts
```

- `--raw`가 없으면 `src/assets/art/town`의 처리본을 원본 캔버스로 되돌려 쓴다. 결과는 조금 흐리다. 원본으로 합성한 지금 파일과 비교하면 픽셀 평균 차이가 약 1/255이고, 상자 차이는 3px 안이다.
- 원본 폴더로 합성하면 지금 파일과 픽셀까지 같다 (확인함).
- `--heroes`가 없으면 영웅 예제의 처리본(`src/assets/art/heroes`)을 원본 캔버스로 되돌려 쓴다. 그것도 없으면 사람 없이 그린다.
- `--png`를 주면 1:1 PNG로, `--debug`를 주면 상자를 그린 지도도 쓴다.

## 게임에서 (홈 = 마을 지도)

`src/render/town/`이 이 `layout.json`과 미리 구운 그림(`src/assets/art/town-map/`)으로 지도를 그린다. 굽기는 `tools/art/town/bake.ts`가 처리본 WebP에 합성기(`page.js`)의 단계를 그대로 해서 만든다. 게임은 지도를 열 때 픽셀을 가공하지 않고 읽어서 GPU로 올리기만 한다 (예전에는 열 때마다 브라우저에서 구워 폰 속도로 수 초가 걸렸다).

- 바닥: 하늘, 바닥 그림(잉크 선 `map.thin`만큼 깎음), 흙 오솔길, 모든 그림자를 바닥 그림의 원래 해상도(1024 px 폭) 캔버스 하나에 그리고, GPU에서 2.4배로 키워 깐다. 가장 큰 텍스처가 바닥 원본 폭이다.
- 그림: 구운 그림자를 떼어 그림자 층으로 보내고, 탑은 층을 쌓고(지도 위 끝 밖은 잘라 낸다), 작은 소품·사람에는 바깥 잉크를 덧그린 뒤 지도 해상도(텍스처 1 px = 지도 1 px)로 줄인다. 배치는 `x, y`(땅에 닿는 점)과 `scale`, 몸통은 다시 재서 맞춘다 (`box`와 3 px 안). 어디에 서는지(기준점, 배율, 접지 그림자의 폭)는 `town-map/map.json`에 적는다.
- 지평선 구름처럼 2048 px보다 넓은 그림은 세로 띠 여러 장으로 나눈다 (오래된 폰 GPU의 텍스처 한계).
- 그리는 순서도 같다: 하늘·바닥·오솔길·그림자 층(바닥 캔버스에 곱하기로 한 번), 지평선 구름(그림자와 겹치는 곳이 없어 순서만 바뀌었다), 땅에 닿는 y 순서의 그림, 굴뚝 연기, 탑의 구름 고리, 구름 띠.
- 시안의 서 있는 영웅들은 그리지 않고, 마을 문 → 상점 → 마을 문을 오가는 손님 용사(기획서 9.3)로 바꿨다. 대장간 문 앞의 드워프는 둔다.
- 손님 길(`src/render/town/layout.ts` GUEST_ROAD): 바닥 그림의 상점 오솔길 입구가 마을 문 오른쪽 기둥 바로 뒤에 있어서, 오솔길 위를 걸으면 기둥에 가려 머리만 보인다. 그래서 손님은 아치를 지나 아치 위쪽으로 나와 기둥 꼭대기 북쪽을 지나 상점 문으로 내려간다.
- 움직임: 굴뚝 연기, 분수 물방울, 구름 띠가 천천히 흐른다. 움직임 줄이기 설정이면 멈춘다.
